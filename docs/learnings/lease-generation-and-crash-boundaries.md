# 本次实现记录：恢复与崩溃边界

1. 响应丢失不等于 Open 没有持久化。只允许已有 token 恢复会把“记录在但浏览器没拿到 token”的视图卡死；显式 owner recovery 可以旋转代号，保持原绑定，而不是另开匿名 view。
2. 仅检查 viewId 是否 active 不够：旧网关 cookie 会在视图重开时复活。票据必须绑定 generation，关闭/恢复后旧代永久无效；有真实 HTTP 回归守住此点。
3. SIGKILL 不能执行 finally。宿主被杀后由独立 guardian 观察 IPC 断开清理；先持久预留，让应用真实写出的数据总能被记录认领。
4. 进程组 leader 如果先退出，旧 PID/PGID 存在误杀风险。独立 launcher 锚定精确拥有的进程组，最终由 guardian 清理；仅进程名称匹配绝不算所有权。
5. stopped 是确认，不是意图。先 stop 请求写 stopping，再确认自有进程清理，最后把状态、租约撤销和通知放进一次快照。反向顺序变异在真实 SIGKILL 切口产生已确认停止而进程仍在的错误，并被测试抓住。
6. 真实进程 fixture、真实浏览器、真实 DSH 是三个不同证据层。本次真实进程和快照强杀通过；浏览器被管理员策略阻断；DSH缺失。把它们混成一个“全部通过”会错误解锁下游。

本文件记录本仓实验结果，不宣称原型已提取、上游应用已适配或目标平台已验收。
